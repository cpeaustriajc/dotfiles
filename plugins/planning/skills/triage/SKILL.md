---
name: triage
description: >
  This skill should be used when the user says "triage #42", "what needs my attention", "can an
  agent take this", "move #42 to ready-for-agent" or "write an agent brief". It sets one state and
  a brief. Design questions: grill.
---

Give each issue or PR one state and one category (`bug`, `enhancement`):

| State | Means |
|---|---|
| `needs-triage` | Not checked. |
| `needs-info` | Waits on the reporter. |
| `ready-for-agent` | An agent can finish and prove it alone. |
| `ready-for-human` | A person must do a named part. |
| `wontfix` | Built already, or rejected. |

Use the team's labels; with none, propose these. Commands:
`references/github.md` or `references/other-trackers.md`. No item named, or a direct order:
`references/requests.md`.

1. Read everything. An earlier triage comment's answers stay settled.
2. Search code, harness, skills, the decision log and closed `wontfix` by concept; show matches.
3. Reproduce a bug, or run a PR's checks: confirmed (code path), not reproduced or vague
   (`needs-info`), or blocked (`needs-triage`, say why). Write checks only for a confirmed bug: an unproven check passes on unchanged code.
4. `ready-for-human` if a check needs a merge, sign-in, secret, device, vendor console, paid
   account or taste. Name each.
5. Recommend in chat: state, category, a three-line reason, where you searched, the repro.
   Open scope questions go to `grill`. Wait for my go.
6. Set labels; post one comment opening `> *This was generated by AI during triage.*`, in its
   state's form from `references/agent-brief.md`. Writes follow `../shape/references/top-down.md`
   ("Write, then check the tree").
