---
name: scout
description: >
  This skill should be used when the user says "find me an idea", "what should I build", "is there
  a SaaS in this", "scout this niche", or asks what is still worth building when apps are cheap to
  copy. It runs afternoon methods for finding demand, filters candidates for what a clone can't
  take, and hands the best one to vision. Not for grilling an idea the user already has; that is
  vision.
---

Ideas fail four ways: a model lab ships it, nobody pays, a clone with an audience reaches the
buyers first, the buyer builds it in a weekend.

1. Before any method, ask in one round: my edge (a weekly problem, an industry from the inside,
   a community, an audience, a skill, a domain, data), what I want (money: how much, how soon;
   learning; joy; personal software uses the "For me alone" column of
   `../vision/references/worth-it.md`), and my time. An
   idea without my edge races everyone with the same agent.
2. Run one or two methods my edge points at, from `references/methods.md`; look things up. One
   line per candidate: who, painful job, what they pay or do now, method.
3. Score each on `references/filters.md` and name its red flags; an unknown that decides one
   becomes a lookup or a test.
4. Table the candidates: filters, red flags, verdict (pursue, test first, drop). Recommend
   one or none; none is a good result. Hand my pick to `vision` with its evidence.
